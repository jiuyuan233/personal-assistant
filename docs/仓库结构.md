# 仓库结构

目录布局照搬 [jiuyuan233/wool-gathering](https://github.com/jiuyuan233/wool-gathering)（只抄结构，不抄功能）：
`scripts/` 放采集与渲染，`data/` 放机器生成的状态，`docs/` 既是文档目录又是 GitHub Pages 根，
`.github/workflows/` 放调度。**参考仓库只读，永远不要往里提交。**

**两类文档要分清**：标 ★ 的是 `finalize` 每 20 分钟重写的生成物，手工改会被覆盖；
标 ● 的是手工维护的原始资料与长文，Actions 不会碰。
README 本身也是生成物（模板在 `scripts/readme_template.md`），
所以给 README 加永久入口必须改模板，不能直接改 README。
`docs/竞赛日历.md` 就是靠模板里的 `## 🧭 目录` 段挂上去的。

★ = 每次运行都会被重写并提交，手改必被覆盖。
● = 人工维护的输入。

## 依赖方向

```
utils ─┬─> dedup ─┬─> study_collector ─┐
       │          ├─> diary_collector ─┤
ai_client ─> prompts                   ├─> main ─> render_readme ─> week_svg
       └──────────> notice_collector ──┘         (只读 data/，不联网)
                  schedule_parser ────┘
```

`render_readme.py` 和 `week_svg.py` **不 import 任何采集器**，也不 import `ai_client`。
这是「finalize 模式零 token」的结构保证——改代码时别把这条线接回去。

## 加一个新数据源要动哪些文件

1. `scripts/<name>_collector.py`：产出 `list[dict]`，字段对齐 [数据结构.md](数据结构.md)
2. `scripts/dedup.py`：选一种合并策略（易变的用新值优先，稳定的用旧值优先）
3. `scripts/main.py`：`COLLECT_MODES` + `HANDLERS` 各加一项
4. `.github/workflows/assistant.yml`：加一条 cron + `case` 分支
5. `data/sources.json`：把可调参数放进去，别硬编码
6. `scripts/render_readme.py` + `readme_template.md`：加展示区块
7. `scripts/notify_feishu.js`：`TASK_TEMPLATES` 加指标正则
8. `docs/数据结构.md` + `AGENT.md`：同步文档
