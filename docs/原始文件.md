## 🔒 脱敏口径

### ICS 课表

只动 `LOCATION:` 一行，别的一个字节没碰。

WakeUp 把教室和老师塞在同一个字段里（`LOCATION:美荟楼1#328 <教师名>`），
老师姓名属于个人信息，全部剥掉：

- **172 条**「教室 + 教师」→ 只留教室（`LOCATION:美荟楼1#328`）
- **14 条**纯教师名（无教室信息）→ 清空为 `LOCATION:`
- 判定规则：末段不含 `0-9` `#` `楼` `室` 就视为人名

**行为后果**：[schedule_parser.py](../scripts/schedule_parser.py) 的 `split_location()`
现在**恒定返回 `teacher=""`**，课表里的教师列会一直是空的。
这是脱敏的代价，不是解析 bug。想要教师名就得用未脱敏的原件，
而原件**不进仓库**（见下方铁律）。

### PDF 竞赛目录

**一个字没改。** 这是学校公开发布的赛事名单，本身不含个人信息，
逐项扫过：手机号形态 0、学号形态 0、邮箱 0、身份证形态 0。
所以它是唯一可以直接当「原件」引用的文件。

ICS 完整性对照（脱敏前 → 脱敏后，**只允许 `LOCATION` 行变化**）：

| 指标 | 前 | 后 |
| --- | --- | --- |
| `BEGIN:VEVENT` | 186 | 186 |
| `SUMMARY` | 186 | 186 |
| `DTSTART` | 186 | 186 |
| 总行数 | 1681 | 1681 |
| 变动行数 | — | **186（全是 `LOCATION`）** |
| 疑似姓名残留 | — | **0** |
| 行尾 | LF | LF（**没被转成 CRLF**） |

复核命令（不需要 Python）：

```bash
# ① ICS 完整性：三个计数必须都是 186，CRLF 必须是 0
grep -c "BEGIN:VEVENT" assets/WakeUp导入课表.ics   # 186
grep -c "^SUMMARY:"    assets/WakeUp导入课表.ics   # 186
grep -c "^DTSTART"     assets/WakeUp导入课表.ics   # 186
grep -c $'\r'          assets/WakeUp导入课表.ics   # 0（必须是 LF）

# ② 确认仓库里没有任何抓包文件（期望无输出）
git ls-files | grep -i '\.har'

# ③ 确认全部历史里也没有（期望无输出）
git rev-list --objects --all | grep -i '\.har'
```

> ②③ 是**移除抓包后新增的守卫**，接手 AI 每次改 `assets/` 都该跑一遍。

## 🔁 换文件时怎么做

学期换了要替换 ICS，流程是固定的：

1. **原件先落到仓库外**（例如系统临时目录），绝不 `git add`
2. 跑脱敏，输出名带 `-脱敏` 后缀
3. 按上面的审计表复核，**疑似姓名残留必须为 0**
4. 额外核对「三个 186」和行尾，确认只有 `LOCATION` 行变了
5. 覆盖 `assets/` 下的旧文件，commit

**抓包不适用这个流程 —— 它根本没有「进仓库」这一步。**
`.gitignore` 拒绝一切 `*.har`，**没有任何例外**：

```gitignore
*.har
*.har.txt
```

不要为了图省事去删 `*.har` 那条规则，也不要再加 `!` 例外 —— 它是最后一道防线，
而上一次开例外就漏了班级 ID。

## 🚫 铁律

1. **抓包永远不进仓库，脱敏版也不行。** 里面可能有 Cookie、手机号、密码、班级 ID。
   `.gitignore` 的 `*.har` 就是拦这个的，**不开例外**。
2. **脱敏后的文件也不许含真实凭据或可定位到人的标识。** 明文值只走环境变量 / GitHub Secrets，
   见 [AGENT.md](../AGENT.md) 第 2 条。
3. **开发期在聊天里贴过的凭据一律视为已泄露**，全部轮换后再填进 Secrets。
4. 临时探测目录（含 cookie、密码）**每轮结束立即删除**。
5. **判断脱敏是否过关，要逐个参数问「这个值能不能定位到人」**，
   不能只数 `REDACTED` 出现了几次。复合参数（`A_B`）尤其要整段遮掉。
