## 🔒 脱敏口径

### HAR（两个文件同一套规则）

**删掉的：**

| 类别 | 具体项 | 替换为 |
| --- | --- | --- |
| 身份/令牌查询参数值 | `cpi` `enc` `stuenc` `workEnc` `examEnc` `appAuthToken` `clazzPersonStr` `token` `access_token` `uname` `password` `uid` `_d` `vc3` `xxtenc` `uf` `_uid` `usersign` `signature` | `REDACTED` |
| 32 位十六进制串 | 会话令牌、头像路径哈希 | `REDACTED` |
| 已知身份字面量 | 手机号、学号、密码、`cpi` 数值 | `REDACTED` |
| 请求体 | `postData.text` 整个丢弃 | `[已移除：请求体可能含凭据]` |
| 表单参数值 | `postData.params[].value` | `REDACTED`（**参数名保留**） |
| 响应体 | `response.content.text` | `[已移除]` |

**保留的（这才是文档价值所在）：**

- 请求方法、完整 URL 路径、**查询参数名**、状态码、时序（`timings`）
- 无害的业务参数值：`courseid` `clazzid` `courseId` `classId` `ut` `unitId` `robotId` `t` `v`
- `log.comment` 里写明了脱敏口径，导入 DevTools 后也能看到

**为什么保留参数名而不是整个删掉**：后续 AI 要复现四步链，靠的就是
「哪个接口带哪些参数」这张骨架。值全是 `REDACTED`，结构一点没少。

> ⚠️ 副作用：32 位 hex 规则会连带命中头像 URL 里的路径哈希，
> 例如 `p.ananas.chaoxing.com/star4/REDACTED/138_78c.png`。
> 这类图片链接在脱敏版里是**打不开的**，属预期行为，不要当成 bug 去修。

### ICS 课表

只动 `LOCATION:` 一行，别的一个字节没碰。

WakeUp 把教室和老师塞在同一个字段里（`LOCATION:美荟楼1#328 <教师名>`），
老师姓名属于个人信息，全部剥掉：

- **172 条**「教室 + 教师」→ 只留教室（`LOCATION:美荟楼1#328`）
- **14 条**纯教师名（无教室信息）→ 清空为 `LOCATION:`
- 判定规则：末段不含 `0-9` `#` `楼` `室` 就视为人名

**行为后果**：[schedule_parser.py](../scripts/schedule_parser.py) 的 `split_location()`
现在**恒定返回 `teacher=""`**，课表里的教师列会一直是空的。
这是脱敏的代价，不是解析 bug。想要教师名就得用未脱敏的原件，
而原件**不进仓库**（见下方铁律）。

### PDF 竞赛目录

**一个字没改。** 这是学校公开发布的赛事名单，本身不含个人信息，
逐项扫过：手机号形态 0、学号形态 0、邮箱 0、身份证形态 0。
所以它是四个文件里唯一可以直接当「原件」引用的。

## ✅ 审计结果

脱敏不是「跑个脚本就完了」，每次都要复核残留。当前状态：

| 文件 | 身份字面量残留 | 32 位 hex 残留 | 未脱敏令牌参数 | `REDACTED` 出现次数 |
| --- | --- | --- | --- | --- |
| 抓包-学习通-脱敏.har | **0** | **0** | **0** | 223 |
| 抓包-空间页-脱敏.har | **0** | **0** | **0** | 25 |

ICS 完整性对照（脱敏前 → 脱敏后，**只允许 `LOCATION` 行变化**）：

| 指标 | 前 | 后 |
| --- | --- | --- |
| `BEGIN:VEVENT` | 186 | 186 |
| `SUMMARY` | 186 | 186 |
| `DTSTART` | 186 | 186 |
| 总行数 | 1681 | 1681 |
| 变动行数 | — | **186（全是 `LOCATION`）** |
| 疑似姓名残留 | — | **0** |
| 行尾 | LF | LF（**没被转成 CRLF**） |

复核命令（Node 即可，不需要 Python）：

```bash
# ① HAR 残留复核。真实字面量只从环境变量读，绝不写进仓库或聊天记录。
#    SCRUB_LITERALS 用逗号分隔，期望每项输出都是 0。
SCRUB_LITERALS='<手机号>,<学号>,<密码>' node -e '
const fs=require("fs");
const lits=(process.env.SCRUB_LITERALS||"").split(",").filter(Boolean);
for(const f of process.argv.slice(1)){
  const s=fs.readFileSync(f,"utf8");
  const bad=lits.filter(L=>s.includes(L));
  console.log(f, "身份残留="+bad.length,
    "hex32="+(s.match(/\b[0-9a-f]{32}\b/g)||[]).length);
}' assets/抓包-学习通-脱敏.har assets/抓包-空间页-脱敏.har

# ② ICS 完整性：三个计数必须都是 186，CRLF 必须是 0
grep -c "BEGIN:VEVENT" assets/WakeUp导入课表.ics   # 186
grep -c "^SUMMARY:"    assets/WakeUp导入课表.ics   # 186
grep -c "^DTSTART"     assets/WakeUp导入课表.ics   # 186
grep -c $'\r'          assets/WakeUp导入课表.ics   # 0（必须是 LF）

# ③ 未脱敏令牌参数：期望无输出
grep -oE '[?&](cpi|enc|stuenc|appAuthToken|clazzPersonStr)=[^&"[:space:]]*' \
  assets/抓包-学习通-脱敏.har | grep -v '=REDACTED'
```

> ① 里的 `<手机号>` 等是**占位符**，跑之前替换成真实值，
> 并且只在本地 shell 里 export，**不要 commit、不要贴进聊天**。
> 三项全 0 才算脱敏过关。

## 🔁 换文件时怎么做

学期换了要替换 ICS，或者重新抓了包，流程是固定的：

1. **原件先落到仓库外**（例如系统临时目录），绝不 `git add`
2. 跑脱敏，输出名必须带 `-脱敏` 后缀
3. 按上面的审计表复核，**三项残留必须全为 0** 才算过关
4. ICS 额外核对「三个 186」和行尾，确认只有 `LOCATION` 行变了
5. 覆盖 `assets/` 下的旧文件，commit

### `.gitignore` 的例外规则

仓库默认**拒绝一切 `*.har`**（防止原始抓包带着 token 误提交）。
为了让脱敏版能进仓库，[.gitignore](../.gitignore) 里开了一条窄口子：

```gitignore
*.har
!assets/*-脱敏.har
```

所以：**文件名不带 `-脱敏` 后缀的 HAR 一律提交不上去**，这是故意的。
不要为了图省事去删 `*.har` 那条规则 —— 它是最后一道防线。

## 🚫 铁律

1. **原始抓包永远不进仓库。** 里面可能有 Cookie、手机号、密码。
   `.gitignore` 的 `*.har` 就是拦这个的。
2. **脱敏后的文件也不许含真实凭据。** 明文值只走环境变量 / GitHub Secrets，
   见 [AGENT.md](../AGENT.md) 第 2 条。
3. **开发期在聊天里贴过的凭据一律视为已泄露**，全部轮换后再填进 Secrets。
4. 临时探测目录（含 cookie、密码）**每轮结束立即删除**。
