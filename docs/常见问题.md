# 常见问题

按「最可能先遇到」排序。排查前先看清 Actions 日志里那行 `===== 个人助手启动 · 模式 X =====`，
确认跑的是你以为的模式。

---

## A. 部署 / 调度

### A1. Actions 完全不跑，schedule 像失效了
三个常见原因，按顺序查：

1. **仓库 60 天没有 push** → GitHub 自动停用定时工作流，页面顶部会有黄条，点「Enable」即可。
   本项目每次有数据变化就提交，正常不会触发；但如果长期无变化（寒暑假），就会停。
2. **默认分支不是 workflow 所在的分支** → schedule 只在默认分支上生效。
3. **高峰期延迟** → GitHub 的 cron 是尽力而为，延迟 5–20 分钟很正常，整点跳过也发生过。
   本项目用 cron 表达式原文判模式，延迟不会导致跑错模式，但**会**导致某次采集被跳过。
   别指望「每 20 分钟准时」，把它当「大约每 20 分钟」。

### A2. 手动 dispatch 了 study，日志却显示 finalize
`workflow_dispatch` 的 mode 输入没选对，或者选的是默认值。
dispatch 时 `INPUT_MODE` 优先于 cron 判断，检查表单里的 mode 下拉。

### A3. 私有仓库跑了一个月后 Actions 被禁用 / 额度超了
免费额度：私有仓库 2000 分钟/月，公开仓库无限，self-hosted runner 无限。

**这不是「优化一下就能省出来」的问题**：Actions 按每个 job 向上取整到分钟计费，
一次 finalize 跑 30 秒也计 1 分钟。每 20 分钟一次 = 2160 次/月 = **至少 2160 分钟，单这一项就超额**。
默认配置（约 103 次/天）是按 **public 仓库或 self-hosted runner** 设计的。

三条路：
1. 仓库转 **public**（无限额度，但 `data/` 里的日记摘录和作业标题会公开）
2. 用 **self-hosted runner**（无限额度；放国内机器还能预防日后学校封境外 IP，见 B3）
3. 保持 private + GitHub 托管 → **必须放宽节奏**，用 [DEV_GUIDE.md 第 2 节](../DEV_GUIDE.md) 的省额度 cron 组合（约 1500 分钟/月）

查实际用量：Settings → Billing → Actions。

### A4. 提交步骤失败 `failed to push some refs`
远端有你本地没有的提交（比如你在网页上手改了文件）。workflow 已经先 `git pull --rebase`，
还失败说明 rebase 冲突了。**不要加 --force**。去 Actions 日志看冲突文件，
本地拉下来手工解决，或者直接在网页上把那个生成物改回上一版让下次运行覆盖。

### A5. 我不想让它自动提交
把 workflow 的「提交数据」步骤删掉即可，采集和飞书照常工作，只是 README 不再更新。
但注意：`data/diary/state.json` 不提交 → 增量判断失效 → 每次都重新处理所有日记文件 → token 暴涨。
**至少要保留 `data/` 的提交。**

## B. 学习通（最容易出问题的一块）

### B1. 日志 `未配置 CX_USERNAME / CX_PASSWORD，跳过学习通采集`
Secrets 没配或名字拼错。必须是这两个名字，全大写。配在 **Settings → Secrets and variables → Actions → Secrets**，
不是 Variables。配完要重新跑一次才生效。

### B2. `login_failed`
按可能性排序：

1. 密码改了 / 账号被锁 → 手动去 `https://dzi.huuc.edu.cn` 登一次确认
2. 学校加了验证码或二次校验 → `fanyalogin` 返回 `status:false`，日志里会打 `msg` 原文，看它说什么
3. **出口 IP 被拒** → 见 B3
4. AES 加密参数变了 → 学校升级超星版本时可能换 key。日志里如果 msg 是「用户名或密码错误」
   而你确认密码没错，就是这种情况，需要重新抓包确认 key

**注意**：日志只打 `data['msg']`，不打完整响应，避免把手机号/token 写进公开日志。

### B3. 所有学校站点都连不上（已实测可达，留作预案）

**2026-11-13 实测结论：可达。** Actions 出口 IP `20.118.38.104`（美国 Azure），
`probe` 10 个目标 **全部可达、不可达 0**：学习通登录 200 / 作业 200 / 课程 200 / 空间 200，
校网公告、教务处、校团委、飞书均 200，Gitee 与 AI 中转 401（可达，只是没带凭据）。
所以**不需要 self-hosted runner，也不需要国内定时任务兜底**。

如果日后学校改版或开始封境外 IP，再跑一次 `probe`（dispatch → mode=probe）确认。
它会打出出口 IP 和 10 个站点的 HTTP 状态码，看 `[probe]` 行：

- 全部超时/403 → 学校封了海外 IP，Actions 这条路走不通
- 只有 passport2 不通 → 登录环节挂了，其余可能还能用
- 全部 200 → 正常

三条退路（详见 [DEV_GUIDE.md 第 4.3 节](../DEV_GUIDE.md)）：
自托管 runner（国内机器）/ 把 study 拆到国内定时服务 / 手动导出作业列表。

### B4. `课程总数：0`
登录成功但课程列表空。可能是 `course_list` 接口地址变了（学校换域名），
改 `data/sources.json` 的 `study.course_list`。也可能是这个账号本学期没课。

### B5. 某几门课 `作业列表被拒（token 或权限问题）`
`enc` 令牌过期或该课权限特殊。少量失败正常（日志会打 `扫描课程：N，失败：M`），
大面积失败说明第③步铸 token 的落地页结构变了，要重新抓 `stucoursemiddle` 的 302 目标页。

### B6. 考试列表返回「参数传递不正确！」
**参数大小写搞混了**。作业接口用 `courseId` / `classId`（驼峰），
考试接口用 `courseid` / `clazzid`（全小写，而且是 clazz 不是 class）。
两个都必须带 `ut=s` + `stuenc=<enc>` + `enc=<对应的 workEnc/examEnc>`。

### B7. 截止时间不准 / 显示 `≈`
`≈` 表示这是**推算值**：列表页只给「剩余1小时12分钟」，不给绝对时间戳，
所以 `deadline = 抓取时刻 + 剩余时长`。误差来自页面倒计时取整（分钟级）。

想拿精确值：`sources.json` 里 `study.fetch_detail: true` + `max_detail` 调大，
程序会对「待完成且没有倒计时」的任务抓详情页补绝对时间（`deadline_exact: true`，`≈` 消失）。
但详情页的日期正则 `DETAIL_DT_RE` **尚未实测验证**，失败会静默退回推算值。

### B8. 明明提交了，清单里还显示待完成
两种情况：

- **互评作业**：状态是「待批阅」但你还没去评别人 → 程序**故意**把它算作 `pending`。这是对的，你确实还有事要做。
- 状态词不在 `classify` 的三张表里 → 落到 `unknown`，不会进待完成清单。
  去日志或 `data/study/tasks.json` 看 `status` 原文，把新词加进 `study_collector.py` 的 `PENDING`/`SUBMITTED`/`DONE`。

### B9. 已完成的任务越积越多
设计如此，不删。README 只把最近 20 项放进折叠块，`docs/data/tasks.json` 保留全量。
真嫌大就手工清空 `data/study/tasks.json` 的 `items`（下次运行会重新填，但 `first_seen` 会丢）。

### B+. 同一门课在 README 里出现两行 / 任务串班
**不是 bug，是数据本来如此**：同一门课可能挂在两个教学班下
（实测英语课 `course_id=201780805` 有 `class_id` 156400069 / 156290484 两条），
所以 14 行是对的。但**任务必须只归到它所属的那个班**。
归组键是 `render_readme.course_key() = (course_id, class_id)`，
若有人改回只用 `course_id`，两行就会显示同一批任务（一行作业数 3、另一行 0，自相矛盾）。
selftest 有 2 条断言守着。

### B+. 「开始超过 7 天」剔除的条数一直是 0
正常。普通作业的 `start_time` 退回 `first_seen`（助手首次发现时间），
而助手是 2026-11-13 才开始跑的，所有任务的 first_seen 都很新。
**真实发布时间在静态 HTML 里取不到**（详情页只有空标签 `作答时间:`，值由 JS 填）。
只有互评任务能拿到真实窗口。等助手跑满一周后这个过滤器才会真正生效。

### B+. 互评任务明明结束了还挂在清单里
检查 `detail_eval_window()` 是否解析到了窗口。日志里应有 `互评窗口截止：… → …`。
没有这行就是正则失配 —— 用 `detail_time_hints(html)` dump 页面片段看真实写法，**别猜正则**。
窗口格式实测是 `互评时间：11-06 07:01 至 11-10 23:01`（**不带年份**）。

## C. Gitee 日记

### C1. `Gitee … → HTTP 401/403`
`GITEE_TOKEN` 失效或权限不足。去 Gitee → 设置 → 私人令牌，确认勾选了 `projects` 权限。
令牌过期就重新生成，更新 Secret。

### C2. `HTTP 404` 但网页上明明能看到那个目录
**中文路径编码问题**。Gitee API v5 要求把中文路径百分号编码后拼进 **URL 路径段**，
不能用 `?path=` 查询参数。代码里用 `quote(path, safe="/")` 处理，
如果你改了路径配置，确认 `data/sources.json` 的 `diary.path` 和网页上的完全一致（包括那两层重复的「个人信息」）。

### C3. 日记改了但没被处理
增量靠 **git blob sha**。检查 `data/diary/state.json`：

- 该文件的 sha 和 Gitee 上的一致 → 程序认为没变。可能是你改完还没 commit/push 到 Gitee
- 该文件不在 `files` 里 → 上次处理失败了，下次会重试
- 文件总数超过 `max_files_per_run`（默认 12）→ 排在后面的这次没轮到。
  按文件名倒序处理（新的优先），多跑几次就都覆盖了。急的话把 `max_files_per_run` 调大

### C4. 名言里混进了名人名言 / 歌词
提示词已经明确禁止，但模型偶尔不听话。两个办法：
在 `DIARY_INSTRUCTIONS` 里加更强的约束，或者直接删掉 `data/diary/quotes.json` 里那条
（按文本去重，只要日记里那句还在，下次可能又被挖出来——所以改提示词才是根治）。

### C5. 同一条待办出现两次
一条 `origin: "checkbox"`、一条 `origin: "ai"` → AI 违反了「不要重复输出复选框里的待办」的约束。
检查那句加粗提示是否还在 `prompts.py` 里。
临时处理：把 AI 那条的 `state` 改成 `cancelled`，合并层会永久跳过它。

### C6. 我在 Obsidian 里勾掉了一个待办，README 里还在
`- [x]` 会被解析成 `state: "done"`，且 checkbox 通道是权威的，会覆盖旧状态。
如果没生效，说明那个文件这次没被处理（见 C3），或者你的复选框写法不标准
（必须是行首 `- [x]` / `* [x]` / `+ [x]`，方括号里是空格或小写/大写 x）。

### C7. 想永久屏蔽某条 AI 挖出来的幻觉计划
手改 `data/diary/plans.json` 里那条的 `state` 为 `"cancelled"`。
**这是唯一允许手改生成物的地方**，合并层见到 cancelled 会直接跳过，AI 再挖到也不会复活。

### C+. 日记里没出现「🤖 助手待办」区块
按顺序排查：
1. 日志里搜 `写回：` —— 若打的是「没有可写的计划，也不新建空日记」，那是**正确行为**：
   选取规则是 `first_seen == 昨天` 或 pid 在 rolling 里。助手刚上线那天所有计划都是今天新增的，
   **首次自然写回落在第二天**。
2. 搜 `日记写回失败` —— 写回异常只 WARN，不影响采集，所以采集成功≠写回成功
3. 搜 `Gitee 写入 … → HTTP 4xx` —— 401/403 是 token 权限不够（需要写权限），
   400/409 多半是**更新没带当前 sha**
4. `data/sources.json` 的 `diary.daily_dir` 是否和真实日记目录一致（当前是 `日`）

### C+. 计划条数暴涨 / 同一条计划反复出现
**助手自己写的区块被当成用户新写的再抽了一遍。**
`diary_collector` 在 `extract_checkboxes()` 和 `ai_extract()` 之前都必须调 `strip_assistant_block()`。
少调一处就会无限自我复制。selftest 有断言守着。
另一个可能：`plans.json` 的 `id` 是 `make_id(text, source_file)`，
写回时若改了文本或路径，pid 就变了，去重抓不住。

### C+. 用户正文被助手改掉了
这是**最严重的 bug**，`upsert_block()` 只允许替换 marker 之间的 span。
检查是否有人改成了「整文件重写」或「按行号截断」。
区块外必须逐字节保留，selftest 的「区块外正文保留」断言就是守这条的。

### C+. 已勾选的待办被助手改回未勾选
合并时 `[x]` 必须优先。`parse_block()` 读到的 checked 状态要并进 `done_ids`，
不能被本次渲染的默认 False 覆盖。同日重复写回必须幂等。

### C+. Gitee 读文件返回 200 但内容是空的
**Gitee API v5 对不存在/已删除的文件返回 HTTP 200 + `{}`，不是 404。**
判断存在与否要看 body 里有没有 `sha`（`read_file()` 已经这么做了）。
只看状态码会误判成「文件存在但为空」，接着不带 sha 去 PUT 就被拒。

## D. 校园公告

### D1. `抓取站点：4，成功：0`
海外 IP 连不上学校站点（见 B3），或学校改版了。先跑 `probe`。

### D2. 抓到了但公告条数很少 / 日期全是 null
学校改版换了 HTML 结构。`notice_collector.py` 认三种日期标记：
`<b>DD</b><span>YYYY-MM</span>`、`YYYY-MM-DD`、`<span>MM-DD</span>`。
链接锚点正则要求 href 形如 `info/数字/数字.htm`。新站不符合就要加模式。
调试办法：把那个页面的 HTML 存下来，喂给 `parse_list` 看输出。

### D3. 日期串到了上一条公告上
这个 bug 修过了：日期常在 `<a>` 外面，回看 200 字符时可能命中上一条的日期。
现在取「最靠近链接的匹配」（`m.end()` 最大）。如果你改了 `_match_date`，别把 `nearest=True` 弄丢。

### D4. 重要竞赛没出现在 README 里
按这个顺序查：

1. `data/notice/notices.json` 里有没有这条？**没有** → 抓取或翻页问题，或标题太短（<4 字被当图片链接丢了）
2. 有，但 `score` 是 0 或 2 → **关键词门把它拦在 AI 之外了**。查 `sources.json` 的 `keywords.gate`，
   标题里没有 gate 词就不会送 AI。往 gate 里加词（如「挑战赛」「立项」）
3. 有，`score >= 3`，但 README 里没有 → 检查 `publish_date`，超过 120 天会被清理；
   或者展示上限 12 条把它挤掉了
4. `block` 词误伤 → 比如标题里有「党委」但其实是创新创业大赛，从 block 里去掉那个词

### D5. `未配置 AI_API_KEY，公告相关度退回关键词打分`
正常降级，不是错误。关键词打分只有 0/2/3 三档，没有语义判断。想要精细评分就配 `AI_API_KEY`。

### D6. `截止日 YYYY-MM-DD 在正文里没有报名截止依据，丢弃：<url>`
**这是校验在正常工作，不是故障。** `deadline_supported()` 要求正文同时满足两条：
出现报名截止语义（`DEADLINE_CUE_RE`：截止/逾期/不予受理/前报送/报名…前/提交…前），
且该日期能在正文里找得到。缺一条就丢弃，README「截止」列显示 `—`。

实测拦下过两类错误：模型把「学院初赛阶段10月1日—10月30日」的结束日当报名截止；
以及凭空编一个正文里根本不存在的日期。**收紧提示词后重抽仍返回同一个错值**，所以别指望改提示词解决。

如果确认某条公告真有报名截止日却被丢弃，按顺序查：
1. 打开那个 url，看正文里截止日是怎么写的。若是 `DEADLINE_CUE_RE` 没覆盖的说法（如「请于…之前完成报名」），补正则。
2. 日期写法没覆盖？`deadline_supported()` 目前兼容 `2026-05-31`／`2026年5月31日`／`5月31日`／`2026.5.31`／`5.31`／`5-31`。
3. **正文取错了**：`body_text()` 必须按 div 深度取 `v_news_content` 内部。容器取错会让日期搜不到，
   表现为「全部丢弃」，很容易误判成校验太严。先跑 `selftest`，那 2 条正文断言会先红。
4. 截止日写在附件（PDF/Word）里而不是正文 → 当前不解析附件，`null` 是正确结果。

⚠️ `ai_detail()` 只在 `deadline` 为空时写值，**存量错值不会被自动纠正**。
要修正历史数据得手工清 `data/notice/notices.json` 里对应记录的 `deadline`（连 `description` 一起清才会重新送 AI）。

### D7. 想加一个新站点
改 `data/sources.json` 的 `notice` 数组，加一项 `{name, url, enabled, pages, weight}`。
先确认那个页面**不需要登录**、链接形如 `info/数字/数字.htm`。不符合就要改锚点正则。

## E. 课表

### E1. 周数不对 / 本周课表是空的
`semester_start` 是从 ICS 反推的众数（实测 `2026-09-07`）。
如果换学期了没换 ICS 文件，周数会一直往后涨，`this_week` 匹配不到任何 event → 空。
**换学期时替换 `assets/WakeUp导入课表.ics`**，然后跑一次 `schedule` 模式。

### E2. 课表显示「课表尚未解析」
`assets/` 下的 ICS 文件不见了或名字不对。文件名必须是 `WakeUp导入课表.ics`（含中文）。
注意 `.gitignore` 不会忽略它，但如果你手动 `git add` 时漏了中文文件名就会缺。

### E3. 节次对不上 / 时间显示奇怪
`schedule_parser.SLOTS` 是硬编码的 11 节作息表（08:00 起）。
学校改作息就要改这张表。匹配不上时代码会取「最接近」的节次，所以不会崩，但可能偏一节。

### E4. 教室和老师分错了
WakeUp 的 `LOCATION` 是 `美荟楼1#328 贾汛` 这种拼接格式，按最后一个空格切。
如果老师名字里有空格，或者只有老师没教室（`胡肄军`），切分规则在 `split_location`，按需调整。

### E+. 课表上的红线不动 / 停在错误的位置
先分清是**哪一条线**：
- **SVG 里的线**：由 `finalize` 每 20 分钟重画，**20 分钟精度是正常的**，不是 bug。
  不动就是 finalize 没跑，或 `docs/week.svg` 没被提交。
- **网页上的覆盖线**：`docs/js/app.js` 的 `startNowLine()` 每 30 秒实时移动。
  它依赖 `docs/data/schedule_geo.json`，**该文件不存在就整条线不显示**（`load()` 返回 null）。
  先跑一次 `finalize` 生成它。

### E+. 网页时间线位置和 SVG 里的线对不上
**Python `time_y()` 和 JS `nowLineY()` 必须是同一套锚点算法。**
改了一边没改另一边就会错位。几何参数（`row_h` / `body_top` / `gutter` / `col_w` / `slots`）
全部从 `schedule_geo.json` 读，不要在 JS 里硬编码。
关键取舍：每节课 45 分钟占满一行，**课间线停在两行交界不拉伸** ——
若有人改成按真实时间线性映射，大课间（08:50→10:05 有 75 分钟）会让线看着像还在上课。

### E+. 网页时间线在周末/假期不显示
正常。JS 按 `geo.date` 算日期漂移平移 `today_col`，超出 0..6 就 `hidden = true`。
课表 SVG 本身只有周一到周日七列。

### E+. 想在浏览器里验证实时线，但页面打不开
**GitHub Pages 尚未开启**（仓库 `has_pages=false`）。开启需要用户点头，别自己开。
在那之前，网页实时线只做过代码审查和 selftest 几何断言，**未在真实浏览器验证**。

## F. 飞书

### F1. 完全没收到消息
1. `FS_WEBHOOK` Secret 没配 → 脚本打一行 `[feishu] 未配置 FS_WEBHOOK，跳过推送` 后 exit 0，**不算失败**。先在日志里搜这句话
2. 配了但 webhook 失效 → 日志里会有 `飞书推送失败` 和返回的 code
3. 机器人被移出群 / 群解散了
4. **用 `feishu-test.yml` 单独测**：dispatch 它，不碰任何数据源，最快定位问题

### F2. 收到卡片但指标全是 0 或「—」
**日志和正则对不上了**。`notify_feishu.js` 的 `TASK_TEMPLATES` 靠正则从日志抠数字，
比如 `/待完成[：:]\s*(\d+)/`。如果你改了采集器的日志文案（哪怕只是把「待完成」改成「待办」），
正则就匹配不到。改日志文案时**必须**同步改 `TASK_TEMPLATES`。

### F3. 卡片颜色不对 / 没有紧急提示
- 洋红 `⚠️` 只在日志里有 `已逾期：N`（N>0）时出现
- 橙色 `⏰` 只在日志里有 `[urgent] …` 行时出现，最多显示 5 条
- 任务失败时红色优先，覆盖上面两种

所以「有逾期但卡片是绿的」= 采集器没打出那行日志 = 那次根本没跑 study 模式（finalize 不采集）。

### F4. 想改卡片样式
改 `notify_feishu.js` 的 `buildCard`。环境变量契约（`FS_WEBHOOK` / `NOTIFY_TITLE` / `NOTIFY_TASK` /
`NOTIFY_STATUS` / `NOTIFY_OUTPUT` / `GITHUB_REPOSITORY` / `GITHUB_RUN_ID`）照搬自
[Lottery-BiliBiliToolB-Web233](https://github.com/jiuyuan233/Lottery-BiliBiliToolB-Web233)，
**别改契约**，否则两个项目的通知脚本就不能互换了。

### F5. 早/中/晚没收到人格消息，只收到运行状态卡片
说明 `/tmp/push-message.txt` 没生成或为空 —— `daily_push.py` 在写文案之前就崩了。
飞书步骤的 `if [ -s ... ]` 会自动落到卡片路径，**所以这种情况仍会报红/报状态，不会静默**。
排查顺序：
1. 日志里搜 `[push] morning 文案 N 字` —— 没有这行就是没跑到写文案
2. 搜 `推送文案 AI 生成失败` —— AI 挂了会 WARN，但**应该走降级而不是崩**
3. 搜 `AI 无输出，改用确定性降级文案` —— 有这行说明降级生效，文案仍会发出去
4. 一言请求失败只 WARN 不阻断，`一言无` 不是故障

### F6. 收到的消息语气不对 / 太客服腔
人格只有一份：`prompts.py` 的 `PERSONA`。**改那里就全改了**（名言点评 + 三个时段共用）。
别在 `daily_push.py` 或各处提示词里复制一份人格描述，那样会漂移。
改完确认硬边界还在：不人格羞辱、不拿外貌/家庭/智力/成绩开刀、不色情、不鼓励自伤。

### F7. 消息里出现了课表 / 上课时间
**这是 bug，用户明确说课表提醒不用它管。**
`diary_facts()` 只读 `data/diary/plans.json` 和 `quotes.json`，**不碰任何 schedule 数据**。
如果有人往事实集里加了课表，删掉。提示词里也写死了这条，但代码层不给数据才是硬保证。

### F8. 消息里编造了任务 / 日期
事实集是确定性拼的，AI 只负责措辞。先核对 `diary_facts()` 的输出（日志里能看到事实摘要），
再看是不是提示词里「只能用今日事实里给出的信息」被删了。
**不要靠加长提示词解决编造**，参照公告截止日的教训：硬约束要在代码里。

### F9. 手动派发多个模式，有的直接 CANCELLED
**同一个 concurrency group 只保留一个 pending run。**
`cancel-in-progress: false` 只保证不打断正在跑的，不保证排队的不被顶掉。
**串行派发，等上一个 completed 再派下一个。** 推送模式有独立 group（`pa-push`），
但仍不要一次派多个推送。

## H. 本地调试

### H1. 没有 Python 环境
本项目的开发机上就没有 Python/Node，所有执行验证都放在 Actions 的 `selftest` 模式里。
你要本地调试的话：装 Python 3.11+，`pip install -r scripts/requirements.txt`，
然后 `python scripts/main.py selftest`（离线、不需要任何凭据）。

### H2. selftest 需要配 Secrets 吗
不需要。它是纯离线断言：倒计时解析、作业/考试 HTML 样例、公告三种日期格式、真实 ICS 解析、合并策略。
**这是第一个该跑的模式**，它挂了说明解析器有 bug，别急着配凭据。

### H3. Windows 上报时区错误
`utils.py` 优先用 `zoneinfo`，缺 tzdata 时退回固定 `UTC+8`（中国 1991 年起无夏令时，等价）。
如果还是报错，`pip install tzdata`。

### H4. 日志里出现 `/tmp/task-output.log` 写不进去
Windows 没有 `/tmp`。设环境变量 `TASK_LOG_PATH` 指向一个可写路径即可，
`log()` 对写入失败是静默忽略的，不影响主流程。

## I. 安全

### I1. 我把密码贴到聊天里了
**立刻改密码**。所有在聊天/截图/抓包文件里出现过的凭据都视为已泄露：
学习通密码、学校官网密码、Gitee 令牌、GitHub PAT、AI key、飞书 webhook。
换完新的再配进 Secrets。

### I2. 抓包文件（HAR）能提交吗
**不能**。HAR 里有完整 cookie、token、手机号。`.gitignore` 已经排除了 `*.har` / `*.har.txt` /
`cookies*.json` / `raw_response*.html`，但别手动 `git add -f`。

### I3. 日志会不会泄露凭据
所有输出走 `utils.log()`，它是唯一脱敏闸口，会屏蔽 `access_token=` / `Bearer` / `sk-` / `ghp_` / `password=`。
**不要绕过它直接 print**。requests 的异常字符串里带着完整 URL 和 token，这是最容易漏的地方。

### I4. 公开仓库安全吗
代码和 `data/` 会被所有人看到。`data/` 里有：你的作业标题、课程名、日记摘录、名言、潜在计划。
**没有**密码和 token（那些只在 Secrets 里）。但日记内容可能涉及隐私，公开前自己权衡。
飞书 webhook 泄露 = 任何人都能往你群里发消息，务必只放 Secret。
