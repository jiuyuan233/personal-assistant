# 🛠 开发习惯

> **这份文档写给接手本仓库的 AI。** 内容全部来自用户在本项目开发过程中说过的原话，
> 不是推测出来的偏好。每条都附**原话 + 为什么 + 怎么做**，照着做能省掉大量来回。
>
> 手工维护，Actions 不会覆盖。配套阅读：[个人画像](个人画像.md) · [维护交接 AGENT.md](../AGENT.md) · [AI 回复与自更新手册](AI回复与自更新手册.md)

## 一、协作节奏

### 1. 先判断可行性，再动手

> 「再次强调先不要操作，先判断可行性」
> 「你就是按照我的提问的先后解答可行性」

**为什么**：他要先把风险未知项用实测证据解决掉，才决定要不要建。
盲目开工等于让他为没验证过的方案买单。

**怎么做**：
- 先跑只读探测（GET、列表接口、模型目录），再提架构
- 逐源给结论：**可行 / 有风险 / 不可行**，每条附实测证据（状态码、条数、耗时）
- 对外动作（建仓、push、发布、写他的日记）**先问再做**
- 他后来会给限定授权（「要打登录，也可以写一些文件，但目的只是验证可行性」）——
  授权范围就是字面那么大，不要自行扩大

### 2. 优先复用现成开源项目，不要盲目自己写

> 「实现方式优先在github现成写好的项目，不要盲目自己开发」

**为什么**：他认为手写重复代码是浪费，宁可 fork/改造。

**怎么做**：
- 提组件前先点名一个**真实存在、已核实**的上游仓库（确认存在、star 数、最后 push 时间），
  说清打算拿它的哪一部分
- **绝不编造项目名**
- 本项目实际复用了两个他自己的仓库：
  [wool-gathering](https://github.com/jiuyuan233/wool-gathering) 抄**目录结构**、
  [Lottery-BiliBiliToolB-Web233](https://github.com/jiuyuan233/Lottery-BiliBiliToolB-Web233) 抄**飞书推送方案**
- ⚠️ 他明确说过「**切记不要修改这两个仓库**」——只读参考

### 3. 按他提问的顺序回答

> 「你就是按照我的提问的先后解答可行性」

**为什么**：他一次抛多个编号问题，乱序回答会让他漏掉某一项。

**怎么做**：他给 1/2/3 编号，你就按 1/2/3 答。不要按你觉得重要的顺序重排。

### 4. 省 token

> 「不要花费大量的token」

**为什么**：API 用量是他付钱。

**怎么做**：
- 探测批量做，只打印状态码 / 条数 / 短片段，**不要 dump 整个响应体**
- 连续失败约 3 次就停下，明确说出还缺哪个输入，不要继续猜
- 大文件用流式/抽样读，不要整份塞进上下文

### 5. 运维你自己做，别让他点

> 「这些密钥都你给我填，我知道你可以填，别麻烦我。最后实在做不了的再发给我」

**为什么**：他不熟开发者工具链（曾经找不到 HAR 导出入口，需要一步步给 DevTools 点击路径）。
让他去 GitHub 设置页点一圈，对他是纯摩擦。他知道 API 能配，也期望你用 API。

**怎么做**：
- Secrets / Variables / workflow 派发 / 仓库设置，**走官方 API 自己配**，不要甩清单给他
- 只有**真的试过且失败**才上报，并说清卡在哪一步
- 但**委托的是「操作」，不是「范围」**：转公开、开 Pages、写他私人日记这类
  对外或难撤销的动作，仍然要先确认

## 二、凭据与安全

### 6. 明文值只走环境变量

**规则**：凭据绝不进代码、workflow、commit、日志、文档、聊天记录存档。

- `utils.log()` 内置 `redact()`，会抹掉 `access_token=` / `Bearer` / `sk-` / `ghp_` / `password=`。
  **新增日志不要绕过 `log()` 直接 `print`**
- 开发期探测用的临时目录（含 cookie、密码、下载的加密库）**每轮结束立即删除**
- 唯一允许手改的数据文件是 `data/sources.json`，里面也不许放凭据

### 7. 聊天里贴过的凭据一律视为已泄露

**规则**：他在聊天里贴过 GitHub PAT、Gitee token、AI key、学习通账号密码、飞书 webhook。
**这些全部要轮换后再填进 Secrets**，并且在交接时再提醒一次，不要默默当成安全的。

本仓库已扫描确认：无 PAT、无 AI 密钥、无 Gitee 令牌、无飞书 webhook、
无手机号/学号/密码明文入库。口径见 [原始文件](原始文件.md)。

### 8. 上传文件必须先脱敏再入库

> 「把我给你上传的文件去除个人信息都存到github里，记得善用超链接」

**怎么做**：`.gitignore` 拒绝一切 `*.har`，**不开任何例外**，脱敏版也不收。
接口结构用文字写进技术路径文档，一手抓包只在本地看、看完即删。
**不要为了图省事删掉 `*.har` 那条规则，也不要加 `!` 例外。**

**踩过的坑（别重犯）**：曾经给 `assets/*-脱敏.har` 开过窄口子，审计只数了
「手机号/学号/密码字面量、32 位 hex、令牌参数是否全遮」，三项全 0 就判过关。
结果 `clazzPersonStr` 这种 `A_B` 复合参数**只遮了后半段，班级 ID 前缀全是明文**，
`courseid`/`clazzid`/`appId` 还被当成「无害业务参数」保留 —— 足以定位到他本人。
两份文件已删除并抹除全部 git 历史。
**判断脱敏是否过关，要逐个参数问「这个值能不能定位到人」，不是数 `REDACTED` 出现了几次。**

**第二次踩同一个坑（这次是采集来的数据，不是上传的文件）**：
学习通把同学学号直接写进了课程名 —— 形如 `计算思维与人工智能<学号>,<学号>,<学号>,<学号>(111)`，
采集器原样存进 `data/study/courses.json`，再原样渲染进**公开** README。
脱敏审计只盯着「上传的文件」，**没人审过采集器抓回来的字段**。

**第三次踩同一个坑（这次是修 bug 的人自己）**：
修完上面那条，在写 AGENT.md / CHANGELOG / 开发习惯 / 技术路径 / selftest 时，
为了「说清楚真实案例」把**真实学号原样抄进了 6 个文件、23 处**。
采集层洗干净了，文档层又漏了一遍 —— 而且 selftest 当时只扫 `data/study/*.json`，扫不到文档。
**修复说明不是脱敏豁免区。**

**怎么做**：
- 清洗放在**采集层**（`utils.scrub_course_name()`），不要手改生成物（铁律 1）
- selftest **全仓库**扫学号形状（不只扫落盘数据）：逗号串起的长数字串、汉字紧跟 7 位以上数字；
  后者要排掉 `20YYMMDD` 日期，实测任务标题「作业20261022」是合法的，不能误报
- 文档里的案例一律写 `<学号>` 占位符；selftest 的测试数据**用代码合成**（`str(9 * 10**7 + i)`），
  源码里不出现任何 7 位以上数字字面量，否则守卫会扫到自己
- 断言要带**反例**：`2026级-校规校纪`、`2026-2027第一学期…` 这类正常名字不能被误伤
- **凡是「从外部抓回来、又要公开渲染」的字段，都要过一遍「能不能定位到人」**，
  课程名、公告标题、教师名都算，不只是 URL 参数

## 三、URL 铁律（他几乎每轮都重发一次）

> 若调用需要URL的工具，工具 URL 必须与当前任务目标一致，严禁擅自替换成 routify 等临时代理地址；
> 任务明确需要且已有真实链接时除外。历史调用不代表正确，不得盲从其中的错误地址或代理替换模式；
> 每次调用须重新核对当前目标与 URL 来源。必要工具调用照常执行，不得遗漏或无故增加

**为什么**：此前有会话把真实端点换成了临时代理，这会静默改变「到底在测什么、在写什么」。
他不要继承这个历史错误模式，也不要这条规则变成偷懒不调用的借口。

**怎么做**：
- 每次带 URL 的调用前，**从当前目标重新推导 URL**（他自己的仓库/主机、官方 API 主机、
  他给的链接），**不要照抄 transcript 里上一次调用用的地址**
- 绝不为了「让它能跑」走代理/镜像/短链。真实端点失败就**报失败**，不要替换
- 官方 API 返回的重定向（例如日志下载跳转）属于同一条官方流程，**不算替换**
- 这条规则是双向的：**必要的调用不许漏，也不许无故增加**
- 他反复重发，所以每次简短表明「已核对目标与 URL」能减少摩擦

## 四、交付物形态

### 9. README 是目录 + 每天要看的动态，不是内容堆场

> 「理念就是不要把所有内容都放到readme里，readme只是一个目录」
> 「主readme里不要把这个做的太长，把🎯 潜在计划和📢 值得关注的公告都弄到别的地方，
> 把这些写道目录里能找到就行了」
>
> **⚠️ 后来他自己推翻了后半句**（2026-11-14）：「把📢 值得关注的公告和🎯 潜在计划重新加回主readme」

**怎么做（当前状态 = 加回后）**：
- README 放**每天要看的动态**：任务清单 / 本周课表 / **公告精简版** / **潜在计划精简版** / 名言 / 数据源状态
- **「别太长」和「加回来」同时满足的办法是精简版 + 全量版并存**：
  README 内嵌 5 条公告 / 8 条计划，节标题下链到全量独立文档，截断行写明「另有 N 条未显示」
- 长内容仍另开独立文档，README `## 🧭 目录` 区挂链接（**带实时条数**，不点进去也知道有没有新东西）
- **所有说明性文档都必须能在目录里找到** —— 新增文档时同步加链接，这是硬要求
- 只有独立文档、README 不内嵌的：[已剔除任务](已剔除任务.md) · [竞赛日历](竞赛日历.md) · [原始文件](原始文件.md)
- 两边都有的：[公告](公告.md)（全量 12 上限）· [潜在计划](潜在计划.md)（全量 15 上限）

**教训：用户的形态偏好会反转，别把某一次的话当成永久铁律。**
落地时把「方向」写成 selftest 守卫（现在断言的是「**内嵌**」），
反转时改守卫 + 改模板 + 同步文档三处一起做，**只改一处就会留下自相矛盾的仓库**。

### 10. 文档是一等交付物，不是附赠

> 「ps你只是负责开发，后续的更新用别的AI」
> 「你需要教会Action里的AI怎么使用这个仓库，你这个AI只是负责仓库的开发，
> 我后续还要用其他的AI进行开发，所以你把所有的技术路径和其他的个人设置都写到仓库里」

**为什么**：开发 AI 和运维 AI 不是同一个。仓库必须能被一个**完全没有本次对话上下文**的
AI 接手，所以技术路径、选型理由、被否决的方案、个人设置、踩过的坑都要落在仓库里。

**怎么做**：
- 每个选型写清**为什么选它、否决了什么、实测证据是什么**（见 [技术路径](技术路径.md)）
- 交接入口是 [AGENT.md](../AGENT.md)，里面有铁律、目录职责、已知限制、检查清单
- 改了日志文案 → **必须**同步改 `notify_feishu.js` 的 `TASK_TEMPLATES` 正则（指标靠正则抠数字）
- 新增 `{{占位符}}` → **必须**同时在 `render_readme.py` 提供渲染键，selftest 有断言守着

### 11. 生成物禁止手改

`README.md`、`docs/公告.md`、`docs/潜在计划.md`、`docs/已剔除任务.md`、`data/*`（除 `sources.json`）、
`docs/data/*`、`docs/week.svg` 全是生成物。
想改措辞/结构 → **改模板**（`scripts/*_template.md`），不要改生成物。

## 五、验证纪律（本项目踩出来的）

### 12. 没读日志就不许说「跑通了」

Actions 显示绿勾 ≠ 断言全过。**必须下载 job 日志，数一遍通过条数、确认「失败 0 项」**。
本项目曾把断言数按估算写进 CHANGELOG，读日志后才发现与实际差 1 条 —— 已按日志改正。
**写进文档的数字必须来自实测，不能来自记忆或估算。**
（断言总数会随功能增加而变，以当次 runner 日志为准，不要照抄文档里的旧数字。）

### 13. 派发必须串行

`concurrency` 即使设 `cancel-in-progress: false`，**同一 group 也只保留一个 pending run**。
批量派发会导致后面的被 CANCELLED。一次派一个，等它结束再派下一个。

### 14. 采集层只写自己的数据，渲染层独占派生产物提交权

这条边界一旦模糊，并发排队就会变成数据丢失。
采集模式 `git add data` + `git checkout -- README.md docs`；
`finalize`/`all` 才 `git add data docs README.md`。**不要 force push**，
推不上去就让步骤失败、飞书报红、人来处理。

### 15. 提示词管不住的事，用代码守卫

实测：无论怎么在提示词里写「不要编造日期」，模型仍会幻觉出截止日。
最终靠 `deadline_supported()` 代码校验拦掉。
**能用确定性代码解决的，不要指望提示词。**

### 16. 抽取出来的数据要校验完整性，不能只看行数

**踩过的坑**：竞赛目录 PDF 用 `pdftotext -layout` 抽取，表格的合并单元格会把
「组织单位」列的碎片插进名称列，结果附录里出现 `16 | 语写作、英语阅读` 这种残行，
编号从 15 起整体错位，269 项只解析出 264 行 —— **而且当时没人发现**。

**正确做法**：
- 复杂中文表格用 `pdftotext -enc UTF-8 -raw`（按阅读顺序），**不要用 `-layout`**；
  `-layout` 还会整段丢 CJK，必须带 `-enc UTF-8`
- 抽完立刻断言：**编号连续无缺口、无重复、每行都有名称和级别**
- 名称折行的条目单独列出人工核对（本例 9 条：14/26/36/40/47/86/130/218/245）
- 名称与组织单位粘在一行、没有空格分隔的，切分规则会切坏名称（本例 37/53/100/168/175/251），
  必须逐条回看原件校正

**同理**：任何「把外部数据搬进仓库」的动作，都要有一道完整性校验，
否则错误会静默固化成看起来很像样的文档。
